# How the game animates farm animals

Notes taken from reading the Build 42 code (decompiled locally, not committed) and the animal anim sets under `media/AnimSets`. They describe the state machine the renderer has to reproduce for `cow`, `cowcalf`, `buck`/`doe`/`fawn`, `ewe`/`ram`/`lamb`, `pig`/`piglet`, `hen`/`cockerel`/`chick`, `turkey`/`turkeypoult`, `rabbit`/`rabkitten`, `raccoon`, `mouse` and `rat`. Class names refer to `zombie.characters.animals`, `zombie.characters.animals.behavior`, and `zombie.ai.states.animals`.

## Anim set folders and node files

Each anim set is a folder of state subfolders (`idle`, `walk`, `eating`, `onground`, `deadbody`, `death`, `falldown`, `followwall`, `hitreaction`, `pathfind`, `trailer`, plus species extras such as `attack`, `alerted`, `onhook`, `zone`, `hutch`, `sit`, `climbfence`), one `animNode` XML file per clip. `AnimNode.java` defaults `m_Looped` to true and `m_SpeedScale` to the literal string `"1.00"`, so a file that omits either field is still a looped, unscaled clip; the field can instead hold a variable name, resolved each frame as `varSource.getVariableFloat(m_SpeedScale, 1.0)`. A file can carry `x_extends="other.xml"`, which loads the other file's fields first and only overrides what's listed. `onground` is always a `*_Dead` pose used for a knocked-down or dead animal, not a rest pose.

## Movement: only two gaits

Every one of the 20 anim sets has exactly `walk/defaultWalk.xml` and `walk/run.xml`, nothing else; no trot or gallop node exists anywhere, and none of the walk, run, eating or sitting nodes use a 2D blend (2D blends only appear in the out-of-scope `alerted` look-around state on the three deer sets).

`run` is gated on the boolean `animalRunning`, a fast "handle" variable (`AnimationVariableHandles.animalRunning`) rather than a plain string. `IsoAnimal` and `BaseAnimalBehavior` set it in a dozen places: fleeing an attacker or a loud/alerting sound (`IsoAnimal.respondToSound`, `IsoAnimal.fleeTo`, `BaseAnimalBehavior.fleeFromAttacker`, `.fleeFromChr`, `.forceFleeFromChr`), running to the mother or away from fire (`BaseAnimalBehavior.wanderIdle`), catching up to the player leading the animal by rope (`BaseAnimalBehavior.walkToChr`), and a periodic random-run roll for calves, piglets, lambs and rabbit kits (`adef.periodicRun`).

`defaultWalk` names `m_SpeedScale` as the variable `animalSpeed` only for cow, cowcalf, the three sheep stages and pig/piglet; deer, poultry and rabbits leave the field unset (a constant 1.00); raccoon, mouse and rat use fixed numbers per node instead of a variable (0.48 on idle, 1.20 on walk, 1.30 on run). The only writer of `animalSpeed` anywhere in the decompile is `BaseAnimalBehavior`: `walkToChr()` sets it to 1.2 while the animal closes the distance to the player leading it, and `followChr()` resets it to 1.0 once the lead is dropped. Species that can't be led this way never touch the variable, so it stays at `AnimNode`'s own default of 1.0, which is why only the leadable barnyard species (cattle, sheep, pigs) reference it at all.

## Idle, eating, and lying down

`idleAction` is the string behind almost every idle-family pose: `"idle1".."idleN"` picks a one-shot flavor clip (count from `adef.idleTypeNbr`), `"eat"` enters the eating node, `"sit"` enters `idleSit`, and `"petting"`/`"happyN"` cover the rest. `BaseAnimalBehavior.wanderIdle()` rolls the idle/happy variants and calls `checkSit()` when `adef.sitRandomly` is set; `AnimalIdleState.animEvent()` clears `idleAction` on the `idleActionEnd` event unless the value is still `"sit"`.

Only species with `sitRandomly=true` get a lying-down pose at all: cow, all three deer stages, all three sheep stages, pig, piglet, raccoon (all three stages), and all three turkey/chicken poultry stages have one; cowcalf, mouse, rat, and both rabbit stages never do (`rabkitten` sets `sitRandomly=false` explicitly in `RabbitDefinitions.lua`, the others simply never set it). `checkSit()` is a once-a-day random window, roughly 3 to 7 hours into the day for 1 to 2 hours, cancelled by hunger above 0.2-0.3, rain without a roof overhead, or an attached (leashed) player.

One oddity: `rabdoe` and `rabbuck` both have `sitRandomly=true` in `RabbitDefinitions.lua`, but the `rabbit` anim set they both point at has no `idleSit` node (only the neighboring `rabkitten` set, which correctly has `sitRandomly=false`, lacks one for a consistent reason). The flag is inert for adult rabbits: nothing plays when it fires.

Cattle, deer and sheep enter and leave the sit pose through a dedicated pair of transition clips (`Cow_Sit_In`/`Cow_Sit_Out`, `DeerStag_IdleToSitting`/`SittingToStanding`, and so on for every set in those three families); poultry instead snap straight into a `Chk_SatIdle01`-style clip with no transition clip at all, and raccoon is the only wildlife set with a real lie-down transition (`Rac_IdleToLieDown`/`Rac_LyingDownToIdle`).

A second string, `eatingAnim`, is only ever written when `adef.eatingTypeNbr>0` (`BaseAnimalBehavior`'s trough/ground/river/puddle/grass eating helpers set it to `"eat"+N`) or unconditionally to `"feed"` from `eatFromMom()`. Pig and piglet each define an `eating2.xml` gated on `eatingAnim=="2"`, but `PigDefinitions.lua` never sets `eatingTypeNbr` for pig, sow, boar, or piglet, so the variable is never written for that species and the clip can never play. Deer, turkey, turkeypoult, mouse, rat, and raccoon only ever define one eating clip, matching their unset `eatingTypeNbr`. cowcalf, piglet and lamb also define a `feeding.xml` (nursing pose) that does play, because their species sets `eatFromMother=true`; the same flag is set on `mousepups`, `ratbaby`, `raccoonkit`, and `rabkitten`, but none of those anim sets has a feeding clip, so those babies nurse using the ordinary eating pose instead.

A third string, `sittingAnim`, only exists for chicken and turkey (`sittingTypeNbr` is set to 1 on `chick`/`hen`/`cockerel`/`turkeypoult`/`turkeyhen`/`gobblers`): it picks a second sitting pose while already seated. `chick` additionally defines `idleSit3.xml` (`sittingAnim=="sit2"`), but `chick.sittingTypeNbr` is also 1, so `Rand.Next(1, 2)` can only ever produce `"sit1"`; `idleSit3` can't be reached from normal play.

Poultry also have a separate `hutch` folder for the nightly coop rest, driven by a `HutchAnimation` string. `IsoAnimal`, `BaseAnimalBehavior`, `IsoHutch`, and `HutchManager` were all checked; none of them writes that variable, so its setter was not present in the decompile.

## Other variables the animation conditions read

- `bMoving`, not `isMoving`: set true on entering `AnimalWalkState`, `AnimalFollowWallState`, or `AnimalPathFindState`, set false on arrival and in `AnimalEatState`, and read back by `AnimalIdleState.execute()` to decide whether to switch into `AnimalWalkState`. `IsoGameCharacter`/`IsoMovingObject` separately expose a real `isMoving()` method, the character's own per-tick displacement check, unrelated to this flag; `IsoAnimal.isAnimalMoving()` is a third, different check again (whether the state machine is currently in the walk, pathfind, or follow-wall state).
- `isAnimalEating` is a live callback registered in `IsoAnimal.registerVariableCallbacks()`, backed by `IsoAnimal.isAnimalEating()`, which just checks `idleAction=="eat"`. The same registration pattern covers `isAnimalAttacking`, `hasAnimalZone`, `isAlerted`, and `shouldFollowWall`.
- There is no `isSleeping` or `isRunning` variable or method anywhere in the animal code. The closest equivalents are `idleAction=="sit"` (`IsoAnimal.isAnimalSitting()`) for lying down, and the `animalRunning` handle for the run gait. `IsoPlayer.isRunning()` does exist, but it describes a human player sprinting; the only place an animal calls it is `BaseAnimalBehavior.fleeFromChr()`, checking whether the human it just spotted is running, to size up how scared to be.
- `ClimbFence` and `climbDown` belong only to raccoon: `IsoAnimal.climbOverFence()` sets `ClimbFence`, and `AnimalClimbOverFenceState` flips `climbDown` and clears `ClimbFence` again once the climb finishes.

## animset mapping

The ten `media/lua/shared/Definitions/animal/*.lua` files (Chicken, Cow, Deer, Mouse, Pig, Rabbit, Raccoon, Rat, Sheep, Turkey) define exactly 30 `AnimalDefinitions.animals` types, three growth/sex stages per species (baby, adult female, adult male), each with its own `animset` string read into `AnimalDefinitions.java`. A baby always gets a dedicated, smaller-bodied anim set (`cowcalf`, `fawn`, `lamb`, `piglet`, `chick`, `turkeypoult`, `rabkitten`), except the smallest wildlife (`mousepups`, `ratbaby`, `raccoonkit`), which reuse their species' single adult set. Adult male and female share one anim set for cattle (`cow` and `bull` both use `"cow"`), pig (`sow`/`boar` both use `"pig"`), rabbit (`rabdoe`/`rabbuck` both use `"rabbit"`), raccoon (`raccoonsow`/`raccoonboar` both use `"raccoon"`), and mouse/rat (both sexes on one set each); sheep, deer, chicken, and turkey instead give the male his own set (`ram`, `buck`, `cockerel`, `gobblers`, distinct from `ewe`, `doe`, `hen`, `turkeyhen`), which lines up with the horns, antlers, comb, and tail feathers that need different geometry. Growth stages chain through `AnimalDefinitions.stages`, for example `cowcalf.nextStage = "cow"` and `cowcalf.nextStageMale = "bull"`.
